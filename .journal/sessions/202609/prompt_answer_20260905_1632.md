--- [83] ANSWER ---
There's no video file. It's a small JavaScript program that draws every frame from scratch onto a `<canvas>`, about eight times a second. Here are the techniques involved.

## 1. The frame clock (the "camera")
`requestAnimationFrame` calls the `tick` function about 60 times a second, in step with your screen. But the program only moves to a new frame every 125 ms, which is 8 fps. That low, choppy rate is on purpose: it's what makes it look hand-animated rather than smooth like software. The film is simply a frame counter `g` that runs from 0 to 495 and then loops.

## 2. Frames are computed, not stored
The film is split into 9 scenes, and each one is a function like `s1(c, f)`. It gets a frame number and draws what should be on screen at that moment, working it out from `f`, for example "the letter appears at frame *i* and falls 36 → 12 → 3 px over three frames". Because each frame is worked out from its number alone, you can scrub, jump to a scene or step backwards, and any frame looks the same every time you land on it.

## 3. Seeded randomness: the "boil"
Real stop-motion shimmers because the animator nudges every piece slightly between shots. I copy that with a **seeded random number generator** (`mulberry32` plus a string hash):
- **Shape seed = the piece's ID.** Each paper cutout gets ragged, hand-cut edges that stay the same for its whole life, so it's the same piece of paper every frame.
- **Jitter seed = frame number + piece ID** (the `jit()` function). Each piece gets a tiny offset (about ±1.2 px, ±0.5°) that's different on every frame but always the same for a given frame. So everything trembles, and scrubbing back to a frame shows exactly the same tremble.

The same trick drives a small **camera shake** for the whole picture and a **lighting flicker**: a nearly transparent warm or dark wash that changes each frame, like a lamp on a real set.

## 4. Faking a paper cutout
Each `piece()` is drawn in three layers:
1. The ragged outline, shifted a few pixels down and right in translucent black, as a **hard drop shadow**. This lifts the paper off the felt.
2. The same outline filled with the paper colour.
3. A faint white edge line, like the bright cut edge of real card.

The felt background and the vignette are drawn once at startup onto off-screen canvases, using thousands of random specks and fibres. Each frame just stamps them back on, which is cheap.

## 5. Motion curves on a low frame rate
Movement uses easing curves (`easeOut`, `easeInOut`) and linear interpolation (`lerp`) between a start and an end position. At 8 fps an ease-out move only gets a few positions, so it reads as a series of deliberate "shots". Some moves are hand-keyed instead, like the letter drop `[-36, -12, 3, 0]`, which gives a small overshoot-and-settle bounce the way an animator would pose it by hand.

## 6. Small tricks in individual scenes
- **Photo into patches (scene 4):** the seascape is painted once off screen. Each patch then uses `drawImage` to copy its own 80×80 square from that picture, and flies along an arc (`sin(q·π)`) with the patches setting off one after another.
- **Yarn (scene 5):** each thread is a quadratic Bézier curve that sags more the farther apart its two tokens are. It's "unspooled" by drawing only part of the curve, up to a progress value that grows each frame.
- **Falling cards (scene 6):** the drop is `y += t²`, which is gravity.
- **Context window (scene 8):** the paper strips and shutters are drawn inside a **clipping rectangle**. The cardboard frame is one shape with a hole cut in it, using the `evenodd` fill rule.

## 7. Onion skin
When you tick the box, the previous frame is drawn into a hidden canvas and laid over the current one at 30% opacity. Real animators do this on a lightbox to check how far things move between frames.

In short, it works like a real stop-motion rig, except that each "photo" is recalculated from its frame number rather than stored. The seeded random numbers are what supply the human imperfection.
